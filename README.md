# Lab : Exceptions personnalisées en Python  ## Objectif pédagogique  Maîtriser la gestion des erreurs en Python en définissant ses propres exceptions pour traiter des cas métiers spécifiques : compte bancaire, réservation d'événements et import de fichiers CSV. Chaque exercice sépare le flux nominal des erreurs métier et applique validation et journalisation.  ## Structure du projet  ``` lab_exceptions/ ├── compte_bancaire.py        # Exercice 1 : code ├── test_compte_bancaire.py   # Exercice 1 : tests ├── reservation.py            # Exercice 2 : code ├── test_reservation.py       # Exercice 2 : tests ├── csv_reader.py             # Exercice 3 : exceptions et charger_csv() ├── main.py                   # Exercice 3 : point d'entrée ├── tests_csv.py              # Exercice 3 : tests ├── articles.csv              # Exemple de fichier pour l'exercice 3 └── README.md ```  Les fichiers `comptes.log`, `reservations.log` et `erreurs.log` sont générés à l'exécution.  ## Prérequis  - Python 3.9 ou supérieur - Aucune bibliothèque externe (modules standard uniquement)  ## Exercice 1 : Compte bancaire  **Fichiers :** `compte_bancaire.py`, `test_compte_bancaire.py`  ### Hiérarchie des exceptions  ``` Exception └── TransactionException     ├── SoldeInsuffisantException     └── MontantNegatifException ```  ### Conception  - `CompteBancaire` : attributs protégés `_nom` et `_solde`, exposés en lecture   seule par des propriétés. - `deposer(montant)` et `retirer(montant)` valident le montant ;   `retirer` lève `SoldeInsuffisantException` si le solde est insuffisant. - `afficher()` affiche le titulaire et le solde.  ### Extensions réalisées  1. Exception pour les dépôts négatifs : `MontantNegatifException`. 2. Journalisation automatique dans `comptes.log` (INFO pour les opérations,    ERROR pour les erreurs). 3. Hiérarchie d'exceptions financières avec `TransactionException`.  ### Exécution et résultat  ``` python compte_bancaire.py ```  ``` Compte: Alice, Solde: 100€ Erreur: Solde insuffisant pour ce retrait. Erreur: Le montant doit être strictement positif. ```  ## Exercice 2 : Système de réservation  **Fichiers :** `reservation.py`, `test_reservation.py`  ### Hiérarchie des exceptions  ``` Exception └── ReservationException     ├── CapaciteDepasseeException     ├── NombreInvalideException     ├── NomClientInvalideException     └── ReservationIntrouvableException   (extension : annulation) ```  ### Conception  - `Evenement` vérifie dans l'ordre : nom du client non vide, nombre de places   strictement positif, capacité suffisante. - Aucune place n'est consommée lorsqu'une erreur est levée. - `Reservation` (dataclass immuable) porte l'identifiant, le nom du client et   le nombre de places.  ### Extensions réalisées  1. **Journalisation** : toutes les tentatives de réservation, réussies ou non,    sont tracées dans `reservations.log`. 2. **File d'attente** (option `file_attente_active=True`) : une réservation qui    dépasse la capacité est mise en attente, dans l'ordre d'arrivée.    `annuler(identifiant)` libère les places et confirme automatiquement les    réservations en attente qui rentrent. 3. **Identifiant client unique** : chaque réservation reçoit un numéro    incrémental.  ### Exécution et résultat  ``` python reservation.py ```  ``` Erreur: Nom du client requis. Réservation confirmée pour Alice (3 places) - n°1. Erreur: Capacité dépassée. Réservation placée en file d'attente (n°2). Événement: Concert — 3/5 places réservées Réservation de Bob (4 places) confirmée depuis la file d'attente - n°2. Événement: Concert — 4/5 places réservées ```  ## Exercice 3 : Import CSV sécurisé  **Fichiers :** `csv_reader.py`, `main.py`, `tests_csv.py`  ### Hiérarchie des exceptions  ``` Exception └── CsvException     ├── FichierIntrouvableException     ├── LigneInvalideException     └── PrixNegatifException ```  ### Format attendu  Fichier texte, séparateur `;`, une ligne par article : `id;nom;prix`.  ``` 1;Clavier;29.90 2;Souris;15.50  3;Écran;199.99 ```  ### Règles de validation  | Cas                                         | Exception                     | |---------------------------------------------|-------------------------------| | Fichier absent (ou chemin vers un dossier)  | `FichierIntrouvableException` | | Nombre de colonnes différent de 3           | `LigneInvalideException`      | | Identifiant ou nom vide                     | `LigneInvalideException`      | | Prix non numérique (`abc`, `nan`, `inf`)    | `LigneInvalideException`      | | Prix négatif ou nul (doit être > 0)         | `PrixNegatifException`        |  Les lignes vides sont ignorées. Les numéros de ligne dans les messages correspondent aux lignes du fichier, lignes vides comprises.  ### Conception  - `charger_csv(chemin)` retourne une liste de dictionnaires   `{"id": str, "nom": str, "prix": float}` ou lève une exception du tableau   ci-dessus. Elle n'utilise aucun `print`. - `main.py` gère les exceptions avec `try / except` (de la plus spécifique à   la plus générale) et affiche un message utilisateur clair. Il retourne un   code de sortie (0 = succès, 1 = erreur). - Les anomalies sont tracées dans `erreurs.log`.  ### Exécution  ``` python main.py                 # lit articles.csv python main.py autre_fichier.csv ```  ``` 3 article(s) chargé(s) :   1 - Clavier : 29.90 €   2 - Souris : 15.50 €   3 - Écran : 199.99 € ```  ## Tests  | Exercice | Commande                                   | |----------|--------------------------------------------| | 1        | `python -m unittest test_compte_bancaire -v` | | 2        | `python -m unittest test_reservation -v`     | | 3        | `python -m unittest tests_csv -v`            |  Tous les tests d'un coup : `python -m unittest discover -p "test*.py" -v`  Les tests couvrent : la hiérarchie des exceptions, les cas nominaux, chaque cas d'erreur, l'état inchangé après une erreur, la journalisation (`assertLogs`) et les messages affichés. Pour l'exercice 3, ils couvrent les quatre jeux de tests recommandés (CSV valide, fichier absent, prix texte, prix négatif).  ## Choix de conception  - Les noms de classes et de méthodes de l'énoncé sont conservés. - Les attributs sont protégés (préfixe `_`) et exposés par des propriétés. - Toutes les exceptions héritent d'une exception de base propre à l'exercice,   ce qui permet de capturer toute une famille d'erreurs avec un seul `except`. - Un prix égal à 0 est refusé (« doit être > 0 » dans l'énoncé) et lève   `PrixNegatifException`. - L'identifiant d'article de l'exercice 3 est conservé sous forme de chaîne.
